# 6 层记忆体系架构规范

> **SKILL 化产物 · v0.2**
> 编制：2026-06-22（v0.2 架构文档）

---

## 1. 总览

6 层记忆体系 = 把 LLM 的记忆行为，按"生命周期 + 结构化程度 + 通道维度"切成 8 个层 + 1 个 L9 增强层。

```
              ┌─────────────────────────────────────────┐
   L9         │ 跨层融合（unified-memory-search）         │  ← 增强层
              └─────────────────────────────────────────┘
                  ↑           ↑           ↑
              ┌─────────┐ ┌─────────┐ ┌─────────┐
   L8         │ 沉淀     │ 教训     │ 长文     │  ← 已结构化
              │ taskreports│ system.md│ Obsidian │
              ├─────────┤ ├─────────┤ ├─────────┤
   L7         │ 向量搜索（Gemini embedding）              │  ← 语义层
              ├─────────────────────────────────────────┤
   L6         │ shared-knowledge（结构化条目，5 类型）         │  ← 隐性知识
              ├─────────────────────────────────────────┤
   L5         │ 短期记忆（9 天窗口，已被 L9 替代）         │
              ├─────────────────────────────────────────┤
   L4         │ 原始记录（sessions/*.jsonl）   │  ← 全量会话
              ├─────────────────────────────────────────┤
   L3         │ 每日日志（memory/YYYY-MM-DD.md）          │  ← 每天 1 份
              ├─────────────────────────────────────────┤
   L2         │ 核心文件（AGENTS/SOUL/USER/...）         │  ← 工作区骨架
              ├─────────────────────────────────────────┤
   L1         │ 当前 session（context）                  │
              ├─────────────────────────────────────────┤
   L0         │ 当前 prompt                              │
              └─────────────────────────────────────────┘
```

---

## 2. 各层规范

### L0 · 当前 prompt

- **存储**：runtime memory（不可持久）
- **生命周期**：单次响应
- **容量限制**：context window（4-200K tokens，看模型）
- **通道维度**：N/A
- **典型用途**：用户当前发送的消息 + 系统提示

### L1 · 当前 session

- **存储**：runtime memory（不可持久）
- **生命周期**：单个会话
- **典型用途**：session 内多轮对话历史

### L2 · 核心文件

- **存储**：`~/.openclaw/workspace/{AGENTS,SOUL,USER,IDENTITY,TOOLS,MEMORY,TODO,PROBLEM}.md`
- **生命周期**：永久
- **更新频率**：每周/月
- **典型用途**：工作区骨架、用户画像、行为规范
- **8 类核心文件**：

| 文件 | 用途 | 大小（v0 评估）| 更新频率 |
|------|------|--------------|---------|
| AGENTS.md | 操作指令 | 每日 |
| SOUL.md | AI 人格 | 周/月 |
| USER.md | 用户画像 | 周/月 |
| IDENTITY.md | AI 身份 | 季度 |
| TOOLS.md | 工具/环境 | 周/月 |
| MEMORY.md | 长期记忆 | 每日 |
| TODO.md | 待办 | 每日 |
| PROBLEM.md | 卡点 | 每日 |

### L3 · 每日日志

- **存储**：`~/.openclaw/workspace/memory/YYYY-MM-DD.md`
- **生命周期**：永久归档
- **更新频率**：每日
- **典型用途**：当天发生的事件、决策、问题
- **格式**：自由格式，建议按时间序 + 关键事件 + 待办 + 卡点

### L4 · 原始记录

- **存储**：`~/.openclaw/agents/main/sessions/*.jsonl`
- **生命周期**：永久归档（受 storage 限制）
- **容量**：随使用时长增长（生产环境实测达 GB 级）
- **典型用途**：全量会话原始数据、自动 transcript
- **通道维度**：provider + sessionId

### L5 · 短期记忆

- **状态**：⚠️ **已被 L9 替代**，仅做兼容
- **存储**：`short-term-recall.json`（9 天窗口）
- **典型用途**：历史版本遗留，新体系不依赖 L5

### L6 · shared-knowledge（隐性知识）

- **存储**：`~/.openclaw/workspace/config/shared-knowledge.json`
- **生命周期**：永久归档
- **数量**：数百条（随使用增长）
- **更新频率**：理论自动（tacit-knowledge-catcher.py），实际 1+ 月未更新
- **5 类型**：

| 类型 | ID 前缀 | 数量 | 用途 |
|------|---------|------|------|
| system-config | `sys-` | <count> | 系统配置 |
| project-state | `pro-` | <count> | 项目状态 |
| conclusion | `con-` | <count> | 经验结论 |
| capability | `cap-` | <count> | 能力/工具 |
| conversation-topic | （无前缀）| <count> | 对话主题（**类型严重不足**）|

### L7 · 向量搜索

- **存储**：OpenClaw 内置 Gemini embedding index
- **典型用途**：语义检索
- **关联**：与 L6/L3/L4 互通

### L8 · 知识沉淀

- **存储**：
  - `taskreports/项目/` — 项目报告
  - `memory/lessons/system.md` — 教训
  - `~/Obsidian Vault/` — 长文/录音/草稿
  - `MEMORY.md` Top 15 — 速查
- **典型用途**：可被外部审计的成品资产

### L9 · 跨层融合（增强层）

- **存储**：`~/.openclaw/workspace/scripts/unified-memory-search.py`（832 行）
- **典型用途**：跨通道 + 时间加权 + 跨层召回
- **三层防御**：

```
α：AGENTS.md 硬约束（不准用旧 API）
β：plugin 替换（统一 wrapper）
γ：SKILL.md 软规范（本文件）
```

## 3. 5 步法工作流

| 步 | 动作 | 涉及层 |
|----|------|--------|
| **写** | LLM 输出 → L2/L3/L4 | L2 / L3 / L4 |
| **存** | 自动捕捉 → L5/L6 | L5 / L6 |
| **检** | 用户查询 → 跨通道搜索 | L7 / L9 |
| **活** | 命中 → 跨层融合召回 | L6 + L3 + L4 |
| **化** | 沉淀 → L8 | L8 |

## 4. L6 ID 命名约定

- **system-config**：`sys-{8-char-hash}` (<count> 条)
- **project-state**：`pro-{8-char-hash}` (<count> 条)
- **conclusion**：`con-{8-char-hash}` (<count> 条)
- **capability**：`cap-{8-char-hash}` (<count> 条)
- **conversation-topic**：无 ID 前缀（仅 1 条，**严重不足**）

`{8-char-hash}` 由 entry key 哈希得到（前 8 字符）。

---

## 5. 通道维度

| 通道 | 标识 | 权重默认 | 隔离规则 |
|------|------|---------|---------|
| **Telegram** | `telegram` | 当前 channel +1000 | 默认只查当前通道 |
| **飞书** | `feishu` / `lark` | +1000 | 默认只查当前通道 |
| **微信** | `openclaw-weixin` | +1000 | 默认只查当前通道 |
| **QQ** | `qqbot` | +1000 | 默认只查当前通道 |
| **Main** | `main` | +1000 | 默认只查当前通道 |
| **WhatsApp** | `whatsapp` | +1000 | 默认只查当前通道 |

**铁律**：用户没明示"跨通道"时，**默认只查当前通道**。

|---------|------|

| 30 天内 | +2 |
| 30 天以上 | +0 |
