# 6 层记忆体系架构规范（L 编号保留）

> **SKILL 配套架构规范 · v1.0（合成基准）**
> 口径：6 层独立存储 + 2 层引用。本文与 SKILL.md「架构总览」表为同一出处口径，不一致处以 SKILL.md 为准。

---

## 1. 总览

6 层记忆体系 = 把 LLM 的记忆行为，按"生命周期 + 结构化程度 + 通道维度"切成 6 个独立存储层 + 2 个引用层（L5/L7，编号保留兼容）。

```
              ┌─────────────────────────────────────────┐
   L9         │ 跨层融合（unified-memory-search）         │  ← 融合检索层
              └─────────────────────────────────────────┘
                  ↑           ↑           ↑
              ┌─────────┐ ┌─────────┐ ┌─────────┐
   L8         │ 沉淀     │ 教训     │ 长文     │  ← 已结构化
              │ taskreports│ system.md│ Obsidian │
              ├─────────┤ ├─────────┤ ├─────────┤
   L7         │ 检索引用层（内置检索或自建本地语义索引）    │  ← 引用层
              ├─────────────────────────────────────────┤
   L6         │ shared-knowledge（结构化条目，4 类活跃）      │  ← 隐性知识
              ├─────────────────────────────────────────┤
   L5         │ 短期记忆（已由 L9 替代，折叠保留）          │
              ├─────────────────────────────────────────┤
   L4         │ 原始记录（双源，见 §2）        │  ← 全量会话
              ├─────────────────────────────────────────┤
   L3         │ 每日日志（memory/YYYY-MM-DD.md）          │ ← 每天 1 份
              ├─────────────────────────────────────────┤
   L2         │ 核心文件（AGENTS/SOUL/USER/...）         │  ← 工作区骨架
              ├─────────────────────────────────────────┤
   L1         │ 当前 session（context）                  │
              ├─────────────────────────────────────────┤
   L0         │ 当前 prompt                              │
              └─────────────────────────────────────────┘
```

> 命名说明：项目早期为 8 层架构，实战收敛后 L5/L7 折叠为"6 层存储 + 2 层引用"。层号 L 编号保留以兼容历史文档与脚本。

## 2. 各层规范

### L0 · 当前 prompt

- **存储**：runtime memory（不可持久）
- **生命周期**：单次响应
- **容量限制**：context window（4-200K tokens，看模型）
- **通道维度**：N/A
- **典型用途**：用户当前发送的消息 + 系统提示

### L1 · 当前 session

- **存储**：runtime memory（不可持久）
- **生命周期**：单个会话
- **典型用途**：session 内多轮对话历史

### L2 · 核心文件

- **存储**：`~/.openclaw/workspace/{AGENTS,SOUL,USER,IDENTITY,TOOLS,MEMORY,TODO,PROBLEM}.md`
- **生命周期**：永久
- **更新频率**：高频项每日
- **典型用途**：工作区骨架、用户画像、行为规范
- **模板提供 8 类（生产部署实测启用 7 类）**：

| 文件 | 用途 | 更新频率 |
|------|------|---------|
| AGENTS.md | 操作指令 | 每日 |
| SOUL.md | AI 人格 | 周/月 |
| USER.md | 用户画像 | 周/月 |
| IDENTITY.md | AI 身份 | 季度 |
| TOOLS.md | 工具/环境（模板已提供，生产未单独建档，工具信息由 AGENTS.md 承载；启用实践见 Roadmap） | — |
| MEMORY.md | 长期记忆索引 | 每日 |
| TODO.md | 待办 | 每日 |
| PROBLEM.md | 卡点 | 每日 |

> 生产部署实证：高频文件当日均有更新；AGENTS.md 在生产中承载了远超模板骨架的行为规则量，属正常演化。

### L3 · 每日日志

- **存储**：`~/.openclaw/workspace/memory/YYYY-MM-DD.md`
- **生命周期**：永久归档
- **更新频率**：每日
- **典型用途**：当天发生的事件、决策、问题
- **格式**：自由格式，建议按时间序 + 关键事件 + 待办 + 卡点
- **生产实证**：日流水连续无断档（写前日志纪律强制）

### L4 · 原始记录（双源）

- **源① 平台原生转录**：`~/.openclaw/agents/main/sessions/`（平台自动记录）
- **源② 物化目录**：`~/.openclaw/workspace/conversations/raw/YYYY-MM/*.jsonl`（save-conversations.py 定期物化，**L9 统一检索的扫描源**）
- **生命周期**：永久归档（受存储限制）
- **容量**：随使用时长增长（生产环境实测达 GB 级、转录文件数千个）
- **典型用途**：全量会话原始数据、通道隔离真理源
- **通道维度**：provider + sessionId

> 历史说明：早期文档分别只写了两个源之一，v1.0 起统一为双源口径。

### L5 · 短期记忆（折叠层）

- **状态**：⚠️ **已被 L9 替代**，编号保留兼容
- **生产实现**：平台内置记忆组件（SQLite 存储、TTL 管理）+ 每日低峰「记忆晋升」定时任务做短期→长期晋升
- **历史设计**：v0 时代的 `short-term-recall.json`（9 天窗口）独立文件**未投产**，仅作存档性 Roadmap 项（跨平台可移植快照需求出现时再启用）

### L6 · shared-knowledge（隐性知识）

- **存储**：`~/.openclaw/workspace/shared-knowledge.json`（唯一活跃路径；早期 `config/` 子路径为历史遗留，已废弃勿用）
- **生命周期**：永久归档
- **数量**：数百条起步，随使用持续增长
- **更新频率**：自动（tkc 捕捉 + 每 2h 增量更新定时任务跑 `l6-incremental-catch.py`）
- **清洗/去重**：随 SKILL 分发（`scripts/shared-knowledge-cleanup.py`，dry-run 报告 → --apply 归档不删原数据）
- **ID 前缀（检测器支持 5 前缀，活跃 4 类）**：

| 类型 | ID 前缀 | 状态 |
|------|---------|------|
| system-config | `sys-` | ✅ 活跃 |
| project-state | `pro-` | ✅ 活跃 |
| capability | `cap-` | ✅ 活跃 |
| conversation-topic | （无前缀）| ✅ 活跃 |
| conclusion | `con-` | 🗄️ 历史前缀——生产已将此类条目整体迁移并入 conversation-topic（迁移脚本随 v0.3 开源） |

> 演化记录：v0.2 文档曾标注"conversation-topic 类型严重不足"；生产环境后来通过迁移脚本把 conclusion 类并入 conversation-topic，4 类活跃即当前稳态。新部署直接按 4 类口径使用。

### L7 · 检索引用层

- **性质**：语义检索的**引用层**（非独立实现），实现形态因部署而异：
  - 平台内置向量检索（如 memory-core 等内置记忆组件）
  - 自建本地语义索引（离线推理、秒级响应；生产部署两者并存）
- **典型用途**：语义检索
- **关联**：与 L6/L3/L4 互通

> 历史说明：早期文档分别写过"Gemini embedding"与"内置 embedding worker"两种说法，均非生产实态，v1.0 起统一为上述实现相关口径。

### L8 · 知识沉淀

- **存储**：
  - `taskreports/<分类>/` — 分类报告（生产部署按研究报告/系统报告/技能增强等建分类目录；早期文档的"项目/"为命名漂移，机制相同）
  - `memory/lessons/system.md` — 教训
  - `~/Obsidian Vault/` — 长文/录音/草稿
  - `MEMORY.md` 速查索引
  - 周蒸馏档案 — 每周低峰定时任务产出（生产已投产，配置未含于开源版）
- **典型用途**：可被外部审计的成品资产

### L9 · 跨层融合（融合检索层）

- **存储**：`unified-memory-search.py`（检索工具本体，随 SKILL 分发）
- **典型用途**：跨通道 + 时间加权 + 跨层召回
- **三层防御**：

```
α：主会话行为规范（AGENTS.md）硬约束（触发词必调）
β：channel-aware 记忆检索插件（生产部署形态）
γ：SKILL.md 软规范（行为模板）
```

- **生产实证**：三层防御全部落地运行；L9 无自动调度 cron（30 分钟自动跑为 Roadmap 项），由触发词硬约束驱动手动调用

## 3. 5 步法工作流

| 步 | 动作 | 涉及层 |
|----|------|--------|
| **写** | LLM 输出 → L2/L3/L4 | L2 / L3 / L4 |
| **存** | 自动捕捉 → L6（L5 已折叠） | L6 |
| **检** | 用户查询 → 跨通道搜索 | L7 / L9 |
| **活** | 命中 → 跨层融合召回 | L6 + L3 + L4 |
| **化** | 沉淀 → L8 | L8 |

---

## 4. L6 ID 命名约定

- **system-config**：`sys-{8-char-hash}`
- **project-state**：`pro-{8-char-hash}`
- **capability**：`cap-{8-char-hash}`
- **conversation-topic**：无 ID 前缀
- **conclusion**：`con-{8-char-hash}`（历史前缀，新条目不再产生——生产已迁移并入 conversation-topic）

`{8-char-hash}` 由 entry key 哈希得到（前 8 字符）。

## 5. 通道维度

| 通道 | 标识 | 权重默认 | 隔离规则 |
|------|------|---------|---------|
| **Telegram** | `telegram` | 当前 channel +1000 | 默认只查当前通道 |
| **飞书** | `feishu` / `lark` | +1000 | 默认只查当前通道 |
| **微信** | `wechat` | +1000 | 默认只查当前通道 |
| **QQ** | `qqbot` | +1000 | 默认只查当前通道 |
| **Main** | `main` | +1000 | 默认只查当前通道 |
| **WhatsApp** | `whatsapp` | +1000 | 默认只查当前通道 |

**铁律**：用户没明示"跨通道"时，**默认只查当前通道**。
